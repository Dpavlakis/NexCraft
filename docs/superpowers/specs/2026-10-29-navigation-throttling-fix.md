# Navigation throttling regression — 2026-10-29

Scope: local test checkout only; no rollout, package changes, new agents or git mutations.

## Cause and bounded policy

Session hardening made admission atomic in SessionStore.admitRequest: equal-clock overlapping requests now really consume the old eight-per-second allowance. It is per browser session entry (not account-wide). Permission emits HTTP 500 for throttling. LayoutCard.onErrorCaptured permanently replaces a child after a rejected mounted promise. useInstanceVersions starts four distinct provider-list reads concurrently and caches errors for 60 seconds, so a shared panel admission failure can turn all providers' pills red without any provider outage.

Initial controlled mounted HTTP fanout: six distinct modpack cards issue six versions reads; three rapid terminal targets add twelve requests (one coalesced detail, folder list, POST stream credential and POST icon download credential each). This smaller 18-admission reproduction initially motivated capacity 24. The final mounted default-page measurement below supersedes that sizing: 24 and 32 both reject non-retryable navigation credentials. BaseInfo calls detail from its hook and its own mount; ManagerBtns also requests it, so API coalescing is material. These are local controlled measurements through actual routers, not a live browser/NAS trace.

Final chosen policy: authenticated browser session token bucket, capacity 48, refill eight requests/second, atomic equal-clock debit, fixed bounded state. This buys six seconds of idle credit; sustained abuse remains bounded by 48 + floor(8 * elapsedSeconds). Anonymous admission retains eight in a sliding second. API-key role checks, admin-route exemptions, proof-specific brute-force limits, logout/revocation checks and middleware order remain intact. Reject with HTTP 429 and Retry-After: 1, without throwing a SessionError or clearing authentication. Never reset admission from ordinary session saves.

Frontend recovery: retry only explicitly enumerated nonmutating GET reads on 429, at most twice, observing a bounded Retry-After. Never retry POST stream/icon credentials, GET action endpoints, password/factor proofs, or other writes. Fence retries against session changes and cancellation; keep existing view-generation/resource guards. Successful recovered reads must not reach LayoutCard's permanent error boundary. Provider errors retain existing error behavior.
